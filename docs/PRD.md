# PRD｜旅行社獲客網站第一版

## 目標與範圍

以週報、簡報或影片引導旅客選擇需求，取得可解釋的行程提案，再自行聯絡旅行社。第一版只用 HTML、CSS、原生 JavaScript。景點與方案資料隨網站發布，可使用本機靜態 JSON，推薦由瀏覽器規則運算。首版無 Supabase、後端 API、帳號、付款或即時報價。

研究資料提供景點及活動事實。可比對的行程、天數與費用由旅行社另行維護。首版驗收可用明確標示「模擬資料」的測試方案。公開模式排除模擬方案。 [週報](weekly-report.md) · [旅遊研究資料](../research/travel-data.json) · [來源索引](../research/sources.md)

## 使用者

- 親子旅客選擇主題與天數，可提出推車或孩子年齡相關的安排需求。
- 情侶旅客依日期與風格選擇水岸散步或期間限定活動。
- 熟齡旅客可提出休息、短步行或輪椅動線等必要條件。
- 旅行社維護方案與正式聯絡窗口，並在收到旅客主動聯繫後覆核提案。

## 頁面與功能

| 頁面或區段 | 主要功能 |
| --- | --- |
| 首頁與週報入口 | 說明三類客群可如何使用，提供週報與「開始找行程」。 |
| 需求表單 | 必填旅遊對象、每人預算上限、天數及風格（可選不拘）。可填出發地、出發日期、同行人數及必須滿足的動線需求，並勾選獨立的「雨天旅遊」偏好，可與任一風格或不拘並用。錯誤顯示於欄位旁並導向第一個錯誤。 |
| 推薦結果與行程介紹 | 顯示最多三個匹配方案。卡片含天數、每人估價與費用範圍、路線、匹配理由、來源、查詢日期及資料狀態。候選另區列出不確定的條件。 |
| 諮詢 | 產生可複製的文字摘要，包含旅客所選條件、方案及待確認事項。只在旅行社提供正式窗口後顯示外部聯絡入口。複製按鈕只回報複製結果，剪貼簿不可用時提供可手動選取的文字。 |

需求保留於目前頁面的狀態供返回修改。網站不收集姓名、電話或電子郵件，不把表單內容送到伺服器或寫入持久儲存。前端、網址、建置產物及 Git 均不可包含密碼或 API Key。

## 預算口徑

- 幣別為新台幣（NT$／TWD），單位為「每人、整趟行程」，表單填正整數上限，包含等於上限的方案。
- 比對使用方案的每人估價上限。固定金額可視為上下限相同。卡片顯示費用包含與不包含項目、估價適用人數、估價來源及有效日。超出適用人數條件或人數未知且估價依人數計算時，列候選待確認。
- 缺價、過期估價、團體總價未經旅行社換算，或費用口徑不同時，顯示「費用待確認」，不納入符合預算的排序。方案未涵蓋的費用另列，頁面標示估價，避免解讀成總支出或正式報價。

## 推薦邏輯

1. 驗證所有必填欄位。天數及預算須為正整數，同行人數若有填寫也須為正整數。「不拘」與其他風格選項互斥。出發日期若有填寫須為台灣時間的今天或之後。
2. 排除已結束、已取消、停用或公開模式中的模擬方案。客群與天數須相符。預算上限、已選的出發地與必要動線也須符合。必要條件未知時只列待確認候選，確認不符則排除。
3. 活動以實際到訪日核對公告展期，計算方式為出發日期加上行程第幾天減一，含展期起訖日。未填日期或休展資訊尚未查證時，含該活動的方案只列待確認候選。已知休展日或展期外排除該方案。
4. 勾選「雨天旅遊」時，先在符合原條件的正式結果中優先顯示有室內參觀安排且支持該評估的景點資料仍有效的方案。雨天評估依本方案的實際安排，屬編輯判斷。推薦卡顯示「雨天優先」及具體原因，當日開放、交通與戶外動線仍須複查。各組再依相符的風格標籤數由多至少排序。未勾選時，直接依風格排序。若選不拘，風格分數為零。同分先依估價上限由低至高，再依方案 ID 排序。理由逐項取自已匹配欄位，每次輸入相同條件皆得到相同結果。
5. 若有正式結果但缺少可優先的雨天方案，保留原條件的推薦並說明。待確認候選維持原分類。無正式結果時顯示「目前沒有符合所有條件的方案」，保留原輸入，提示造成無結果的條件及可選行動，例如修改天數、調整預算或複製需求諮詢。若有待確認候選，只列尚未核實的原因。任何條件變更皆由旅客確認後重新搜尋。

## 資料欄位

| 資料物件 | 欄位 |
| --- | --- |
| 景點與活動 | 沿用研究資料的 `id`、`name`、`type`、`region`、`venue`、`features`、`audiences`、`eventDates`、`status`、`sources`、`pendingChecks`。活動日期為起訖日，常設景點可填空值。 |
| 方案 | `id`、標題、客群、適用出發地、天數、風格標籤、每日停靠點（景點 ID、行程第幾天）、雨天評估（依據景點 ID、理由，未評估時留空）、必要條件支援狀態、每人估價上下限及適用人數、包含／不包含項目、估價來源、查詢日期、估價與方案有效日、資料狀態及待確認事項。 |
| 需求 | 客群、預算上限（TWD／每人／整趟）、天數、風格、出發地、出發日期、必要限制、選填同行人數及雨天旅遊偏好。 |
| 推薦與諮詢 | 推薦方案 ID、查詢條件、推薦理由、查詢日與來源、待確認項目、可複製諮詢摘要。 |

## 資料過期與待確認

首版採保守的**編輯規則提案**。常設景點可使用最後查詢日後 30 日的複查期限，活動採 7 日。台灣時間過了期限日即標「資料過期」。有較早的官方有效日、方案有效日、展期結束日或估價有效日時，各欄位採較早者。日期缺漏或格式不明時標「待確認」。估價必須另有有效日。

| 狀態 | 顯示與推薦處理 |
| --- | --- |
| 已驗證 | 顯示來源、查詢日期及查核涵蓋範圍。仍需複查的票務或動線分欄列出。 |
| 待確認 | 就地顯示「待確認」及具體欄位，如「木棧道通行待確認」。影響必要條件或費用時移到候選區。 |
| 資料過期 | 顯示「資料過期」、最後查詢日與原來源。過期欄位不作推薦依據，關鍵資料過期的方案只供人工查核。 |
| 活動已結束或取消 | 退出推薦及候選區。若週報仍保留歷史內容，則標「活動已結束」或「活動已取消」。 |
| 模擬資料 | 測試介面、卡片及複製摘要均標「模擬資料」。公開模式隱藏。 |

## 響應式版型

| 視窗寬度 | 版型 |
| --- | --- |
| 手機，低於 768 px | 表單與結果單欄，主要按鈕容易點按。 |

所有尺寸保留完整可讀的狀態與來源。「雨天旅遊」選項與說明可換行，鍵盤可勾選。鍵盤可走完表單、修改條件與複製摘要。焦點可辨識，結果數與錯誤可由輔助技術讀取。320 px 寬無全頁水平捲動。

## 驗收條件

| 情境 | 通過條件 |
| --- | --- |
| 三類旅客 | 親子、情侶、熟齡各一筆測試案例可從首頁完成需求選擇，結果至多三筆且理由與條件相符。 |
| 預算邊界 | 每人估價上限等於上限可列為匹配，超過則排除。缺價、團體未換算價格及過期估價不列為正式匹配。 |
| 行程日期 | 多日行程用活動當日而非出發日核對。測通過展期首末日、排除展期外及已知休展，未確認休展時另列候選。 |
| 雨天旅遊 | 勾選後室內方案在正式結果中優先，評估有明確理由，摘要包含所選偏好。取消勾選恢復原排序。無合適室內方案時提示並保留原結果，過期或待確認方案不得提升為正式推薦。 |
| 無結果 | 原需求保留。提供修改或諮詢，介面不自動放寬條件。 |
| 過期與未知 | 超過複查期限的資料顯示最後查詢日期。必要動線未知不顯示為符合。已結束及取消活動不出現在結果。 |
| 諮詢與隱私 | 可複製摘要或手動選取，回饋訊息與實際操作一致。未配置聯絡窗口時仍可複製，無表單資料外送、前端秘密或 Supabase 依賴。 |
| 響應與鍵盤 | 320、768、1280 px 逐一檢查。所有必填欄位、推薦狀態及來源可讀，鍵盤可完成流程。 |
